## [2026-06-01] Use ngspice as the simulator

**Decision:** ngspice is the primary simulation engine.

**Reason:**
- Fully scriptable via subprocess — no GUI required
- Industry-standard SPICE format (.sp files) — portable
- Handles transient, AC, and DC analysis
- Open source, free for commercial use

**Alternatives rejected:**
- LTspice — GUI-dependent, hard to automate, Windows-first
- Qucs-S — less mature, smaller community
- PySpice — adds abstraction layer, harder to debug convergence

**Known issue:** Non-linear elements (diodes, MOSFETs) can fail to converge.
Workaround: Add `.options RELTOL=0.01 ITL1=500` on retry.

## [2026-06-01] Python 3.10+ as primary language

**Decision:** All production code in Python 3.10+.

**Reason:**
- Best scientific library ecosystem (numpy, scipy)
- Easy subprocess control of ngspice
- Strong AST tooling (used by `progress_gen.py` for function introspection)
- LLMs generate reliable Python

**Alternatives rejected:**
- JavaScript — poor scientific library ecosystem
- Rust — slower iteration with AI coding

---

## [2026-06-01] SPICE netlist as canonical schematic format

**Decision:** Internal representation is SPICE (.sp), not custom format.

**Reason:**
- Industry standard — accepted by ngspice, LTspice, KiCad
- Human-readable, easy to debug
- Direct path to PCB tools

---

## [2026-06-02] pytest with one-test-per-function convention

**Decision:** Every function `foo()` in src/ has a matching `test_foo()` in tests/.

**Reason:**
- Lets `progress_gen.py` map functions to tests by name
- Makes `progress.yaml` reliably show per-function status
- Forces test coverage discipline

---

## [2026-06-02] state.json + progress.yaml are derived, not hand-edited

**Decision:** Both LAYER 4 files are auto-generated by `tools/regen_state.py`
and `tools/progress_gen.py` from reality (tests + ast + git).

**Reason:**
- Hand-maintained state drifts from reality within days
- Reality (tests pass/fail, files exist) is the only trustworthy signal
- Removes the "worker claims X is done but it isn't" failure mode
